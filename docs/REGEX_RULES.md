# 自定义正则识别规则使用指南

[项目首页](../README.md) · [TXT 转 EPUB](TXT_TO_EPUB.md) · [章节编号检查](NUMBERING_CHECK.md)

自定义正则适合识别 `233.第233章 比试`、英文标题等特殊章节格式。它只决定哪些原文行是标题、标题属于哪一层，以及显示什么标题；源 TXT 不会被改写。

## 快速处理带前置序号的章节

1. 导入小说，打开左侧“识别规则”。
2. 展开“高级规则 · 自定义正则”，点击“添加前置序号示例”。
3. 检查名称、表达式和章节层级。示例默认使用层级 3，与默认“章”相同；如果修改过关键词层级，请相应调整。
4. 点击“测试当前文件”。查看命中数量、原文行号及“原标题 → 提取后标题”，确认普通正文没有被误判。测试不会改变当前目录。
5. 点击面板底部的“应用识别规则”。页面目录、正文预览标题和 EPUB 的 XHTML、NAV、NCX 标题将同步使用识别结果。

没有导入小说时，也可以在“测试文本”输入几行样例，然后点击“测试文本”。无需为了测试而导入文件。

“添加前置序号示例”使用的表达式如下，可直接复制到表达式输入框：

```regex
^[0-9０-９]+[ \t　]*[.．][ \t　]*(?<title>第[0-9０-９零〇一二两三四五六七八九十百千万]+章.*)$
```

| 原文行                     | 是否由此规则识别 | 显示标题                   |
| -------------------------- | ---------------- | -------------------------- |
| `233.第233章 比试`         | 是               | `第233章 比试`             |
| `233. 第233章 比试`        | 是               | `第233章 比试`             |
| `２３３．第２３３章 比试`  | 是               | `第２３３章 比试`          |
| `233.第二百三十三章 比试`  | 是               | `第二百三十三章 比试`      |
| `233.普通编号列表`         | 否               | 仍作为正文                 |
| `他读到了233.第233章 比试` | 否               | 仍作为正文                 |
| `第233章 比试`             | 否               | 可由原有“章”关键词规则识别 |

示例要求前置序号和句点存在；它不会转换编号的字符形式，也不要求前置序号与“第…章”中的编号相同。章节仍按原文顺序排列。

## 规则字段与匹配顺序

| 字段或操作 | 使用方式                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 名称       | 为规则起一个易于辨认的名称，例如“前置序号章节”；最多 40 个字符         |
| 表达式     | 填写单行 JavaScript 正则正文，最多 1,000 个字符；不加 `/ /` 或末尾标志 |
| 启用复选框 | 控制该规则是否参与识别；禁用规则保存时仍会校验其名称、表达式和层级     |
| 章节层级   | 1–10，数字越小层级越高；相同数字表示同级                               |
| 上下箭头   | 调整正则规则的优先顺序，越靠上越先匹配；不会更改章节层级               |
| 删除按钮   | 删除该条规则，点击应用后生效                                           |

每一行先按正则列表从上到下尝试，采用第一条命中的规则；没有命中任何已启用正则时，才继续尝试现有关键词规则。一行只生成一个标题。

系统逐行去除首尾空白后匹配，并要求表达式匹配完整一行。即使省略 `^` 和 `$`，系统仍会限制为整行匹配。规则只在配置的“标题长度上限”内尝试：默认 60 字，可设为 4–500 字；长度按包含前置序号的完整标题计算，提取标题不能绕过这个限制。

固定使用 JavaScript 的 Unicode（`u`）模式，不提供其他标志。大小写敏感；无法通过在表达式末尾添加 `i`、`g` 或 `m` 改变匹配方式。

## 如何提取显示标题

使用名为 `title` 的捕获组指定显示标题：

```regex
^[0-9]+\.[ \t]*(?<title>第[0-9]+章.*)$
```

对 `233.第233章 比试`，整个表达式负责识别这一行，`(?<title>...)` 中匹配的内容负责显示，因此标题为 `第233章 比试`。

如果只希望显示“比试”，可改为：

```regex
^[0-9]+\.第[0-9]+章[ \t]+(?<title>.+)$
```

如果希望保留完整的 `233.第233章 比试`，不要定义 `title` 组：

```regex
^[0-9]+\.[ \t]*第[0-9]+章.*$
```

普通捕获组 `(...)`、`(?<chapter>...)` 等其他名称不会用于标题提取。定义了 `title` 组，但它提取为空白、空字符串或在某个分支中没有参与匹配时，会提示规则名称及原文行号，阻止应用；请让所有匹配成功的分支都能提取出非空标题。

以上三个简化例子只覆盖半角阿拉伯数字和半角句点。需要全角数字、全角句点或中文数字时，可使用前面的完整示例。

## 其他可复制的例子

识别 `CHAPTER 12` 或 `CHAPTER 12 The Trial`，保留整行作为标题，同时将 `12` 提供给编号检查：

```regex
^CHAPTER[ \t]+(?<number>[0-9]+)(?:[ \t]+.+)?$
```

此表达式只匹配大写 `CHAPTER`。如果原文使用 `Chapter`，将表达式中的 `CHAPTER` 改为 `Chapter` 即可。应用规则后，在“查看编号检查”中勾选对应正则系列。

识别 `卷一 山川`、`卷12 远行` 一类卷标题，建议层级设为 1：

```regex
^卷(?<number>[0-9０-９一二三四五六七八九十]+)[ \t　]+.+$
```

## 测试结果怎么看

- “测试文本”使用输入框里的文本，不套用当前小说的人工纠错记录；支持最多 20,000 个字符，Windows 换行会统一处理。
- “测试当前文件”使用完整小说及当前文件已有的合并、空章节删除记录，同时使用尚未应用的规则草稿。
- “共识别”包含正则和关键词规则识别出的全部标题；“正则命中”只统计正则识别出的标题。
- 样例区只展示前 20 条正则命中结果，但数量统计覆盖完整测试输入；每条显示原文行号、规则名称、层级、原标题及提取后标题。
- 原标题展示时会去除首尾空白；实际原文保持不变。检查规则时既要看命中数量，也要核对样例和正文。
- 改动规则、测试文本、标题长度或当前文档后，旧测试结果会清除。测试通过后仍需点击“应用识别规则”才会更新目录。

## 与现有功能如何配合

- 可同时定义 `title` 和 `number`，例如 `^(?<number>[0-9０-９]+)[.．]\s*(?<title>.+)$` 将 `233. 比试` 显示为“比试”，同时保留编号 233。`number` 为空或无效时，标题仍能命中；在所选检测范围内会列为未解析编号。没有 `number` 时会尝试提取标准“第…章”等编号。详见[章节编号检查](NUMBERING_CHECK.md#自定义正则的-number-捕获组)。
- 自定义形式若未提取到标准编号类型，会按正则规则单独分组。上面的 `卷一` 写法可以检查该正则系列的编号，但不会自动当成“按卷／册”模式里的重置边界。
- 标题提取只改变显示：目录、预览标题、EPUB 标题同步更新，原文行号和正文范围不变。
- 点击“并入上一节”时，完整原标题行会恢复为正文，包括前置序号，例如 `233.第233章 比试`。
- 删除空章节、撤销及重做继续有效；修改规则后也会保留当前文件的人工纠错记录。
- 已应用的正则规则与关键词规则一同保存在当前浏览器，刷新后可继续使用，但小说仍需重新导入。测试文本和小说正文不会持久保存。
- “恢复默认”会重置关键词规则、标题长度，并清空自定义正则；点击应用后生效。

## 常见问题

| 现象                 | 检查方法                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------- |
| 提示语法错误         | 检查括号和方括号是否配对、反斜杠是否正确；表达式输入框里不需要写成 `/表达式/u`，也不需要把 `\d` 写成 `\\d` |
| 没有命中             | 检查是否启用、整行格式是否吻合、数字/句点是否为全角、大小写是否一致，以及原标题是否超过长度上限            |
| 命中过多             | 缩小表达式范围，避免使用会把普通正文也识别成标题的 `^.*$`，再测试当前文件                                  |
| 层级错误             | 调整“章节层级”；上下箭头只调整匹配优先顺序                                                                 |
| 提示空标题           | 检查 `title` 捕获组及各个可选分支，确保每次命中都能提取出非空内容                                          |
| 提示超时             | 简化表达式，避免 `(a+)+` 这类嵌套重复；先测试少量代表性文本，再测试当前文件                                |
| 已编辑但目录没有变化 | 点击“应用识别规则”；测试按钮不会提交修改                                                                   |

每个任务使用独立匹配 Worker。启动限时 15 秒，就绪后连续 2 秒没有进度就会终止任务；正常持续报告进度的整本扫描可以超过 2 秒。可随时点击“取消”。语法错误、空标题、超时或取消均不会覆盖已有文档和目录。

最多配置 20 条正则。使用正则会增加临时内存占用，处理大文件时可只启用需要的规则。
