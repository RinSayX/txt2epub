# TXT 小说转 EPUB 技术方案

依据：README.md。日期：2026-10-31。方案制定时仅有需求文档；首版已按下述方案实现，运行及验证方法见 [README.md](../README.md)。当前目录和职责边界见 [项目结构](STRUCTURE.md)。

## 1. 已确认的产品决定

以下六项已在本次讨论中由用户确认：

| 项目     | 确认结果                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------- |
| 处理位置 | 纯浏览器本地处理，不上传小说文件                                                                                     |
| 使用规模 | 以电脑端为主，允许导入大文件；超过 50MiB 时提示，继续处理，不设文件大小硬上限                                        |
| 导出格式 | 只导出 EPUB3，同时增强旧阅读器兼容性                                                                                 |
| 识别规则 | 支持关键词、层级排序、无编号标题；首版不开放自定义正则                                                               |
| 误判纠正 | 只取消所选标题，保留其子章节，重建目录层级；提供撤销                                                                 |
| 正文排版 | 非空行作为段落，不自动拼接正文；按后续要求去除段首空白和章末空白行，默认保留段间空行，支持可选自动清理；保留行内空格 |

后文涉及的技术栈、默认参数、界面及开发顺序为工程建议，可继续调整。

原始需求中“兼容 epub2 和 epub3”按本次确认解释为“输出 EPUB3，增强旧阅读器兼容性”，不承诺生成符合 EPUB2 规范的文件。README 已同步此口径。

## 2. 功能范围与用户流程

首版流程：选择 TXT → 检查编码 → 自动识别章节 → 调整规则和层级 → 预览与纠错 → 填写书籍信息 → 导出 EPUB。

建议首版提供：

- 单文件导入，编码自动判断及手动切换。
- 多层目录树、章节数量统计、正文预览、疑似误判提示。
- 关键词增删、启停、层级排序和规则重新应用。
- 取消误判标题、撤销与重做。
- 书名编辑（默认取文件名）、可选作者、语言设置（默认简体中文）。
- 解析和导出进度、取消操作、错误反馈。

账号、云端书架、批量转换、封面上传、正文编辑、自动去广告、繁简转换、章节内容拖动排序和离线安装建议留到后续版本。静态部署与处理过程不联网，不等于首次打开网页也能离线使用。

## 3. 架构与技术选型

建议使用 React + TypeScript + Vite 构建静态单页应用。React 管理规则面板、目录选择和预览状态，TypeScript 约束解析及导出模型，Vite 提供开发与静态构建。参考：[React](https://react.dev/learn)、[TypeScript](https://www.typescriptlang.org/docs/)、[Vite](https://vite.dev/guide/)。

| 模块           | 职责                                   | 选择理由                                         |
| -------------- | -------------------------------------- | ------------------------------------------------ |
| UI 主线程      | 文件选择、规则配置、目录树、预览、下载 | 交互与计算分离                                   |
| 文档 Worker    | 解码、行索引、标题识别、纠错投影、导出 | 减少长任务对界面的阻塞                           |
| 文本与目录核心 | 纯 TypeScript 函数                     | 可脱离 UI 验证，后续可复用                       |
| EPUB 生成器    | XHTML、OPF、NAV、NCX 和资源清单        | 明确控制层级、阅读顺序及兼容策略                 |
| ZIP 打包       | fflate                                 | 支持浏览器及流式 ZIP；采用显式顺序添加条目的接口 |
| 应用状态       | React reducer/context                  | 首版规模下无需额外状态库                         |

fflate 提供 ZIP、流式处理和异步接口，最终选定版本后固定依赖及锁文件；不以库宣传的性能作为本项目性能保证。参考：[fflate 官方说明](https://github.com/101arrowz/fflate)。

数据流：

```text
TXT File
  → Worker 解码与原文存储
  → 行索引 + 候选标题
  → 用户规则 + 人工纠错记录
  → 按原文顺序排列的内容段 + 派生目录树
  → UI 按需预览 / Worker 生成 EPUB → Blob 下载
```

Worker 保有正文，主线程只接收目录信息及当前预览片段，避免每次操作跨线程复制整本小说。消息携带 documentId、revision 和 requestId，丢弃过期任务结果。耗时循环分批执行并让出事件循环，使进度和取消消息能够被处理。

## 4. TXT 导入与编码

1. 读取文件字节，优先识别 UTF-8、UTF-16LE/BE 的 BOM。
2. 无 BOM 时尝试严格 UTF-8 解码；失败后评估 GB18030、GBK 和 Big5 等候选编码。
3. 使用解码错误、异常字符及中文文本特征辅助判断；展示编码及文本样本，允许用户手动切换。
4. 自动判断并非可靠识别：合法字节可能对应多种编码，不能仅凭“解码成功”确定编码。
5. 内部建立统一换行的文本视图及行起始偏移表，保留原始 File 用于重新解码。识别时使用的去首尾空白、全角数字转换不回写正文。

采用浏览器 TextDecoder，输出统一 UTF-8。支持的编码及解码行为依据 [WHATWG Encoding Standard](https://encoding.spec.whatwg.org/)。

空文件阻止继续处理；没有标题时提示并允许按整本单章节导出。首标题前的文本完整保留，作为“简介”内容段；无标题时默认以书名作为单章节标题。

按后续要求，取消原有 20MiB 硬上限。仅当文件大于 50MiB（50 × 1024 × 1024 字节）时，在导入期间及导入后展示大文件提示，不要求额外确认，也不阻止处理；恰好 50MiB 不提示。前端和 Worker 均不按文件大小拒绝导入。提示随当前处理的文件切换，失败或取消后恢复为已导入文件对应的提示。实际可处理大小受浏览器和设备内存限制。

## 5. 标题识别与多层目录

### 5.1 规则模型

规则包含 ID、字面关键词、层级、是否启用、匹配类型。匹配类型分为“编号标题”和“无编号标题”。关键词按字面值处理并转义，不作为用户正则执行。

初始层级按 README 示例设置为“卷 → 册 → 章 → 回”，允许用户调整；也允许多个关键词使用相同层级，例如将“章”和“回”视为同级。

编号标题识别示例：`第一卷 起始`、`第12章 夜雨`、`第１２回 相逢`。支持常见中文数词及阿拉伯数字；编号用于识别和提示，不重新编号，不按编号重排正文。

无编号规则默认提供“序章、楔子、尾声、后记、番外”，可配置层级。建议匹配完整独立行，或“关键词 + 明确分隔符 + 副标题”，例如“番外：重逢”，避免把“番外的故事还没开始”直接当作标题。

### 5.2 识别策略

- 逐行识别，标题必须从去除行首空白后的行首开始，编号结构后允许副标题。
- 建议标题行长度默认上限为 60 个 Unicode 码点，可调整；长行通常作为正文。
- 空行邻接、同类标题重复出现、编号连贯性等仅用于提示可信程度，不据此删除文本。
- 句中“他读到了第十二章”不匹配；独立行形式的正文引用仍可能误判，由人工纠错处理。
- 关键词重叠时优先更长的字面关键词；冲突规则在配置时提示处理。

首版采用确定性规则，不依赖 AI 或外部服务。对固定数量的规则，全文扫描随文本长度近似线性增长；不承诺自动识别完全准确。

### 5.3 目录树构建

按标题在原文中的顺序，用栈维护层级：遇到新标题，弹出同级及更深节点，将它挂到最近的较浅层节点下；找不到则作为根节点。

允许缺层，例如“卷 → 章”，不自动虚构“册”。同一层级的编号可以在新卷中重新开始。无编号标题也使用其配置层级参与构建。

区分两类结构：目录树负责嵌套导航；按原文顺序排列的内容段负责正文及 EPUB spine。卷、册等父节点的直属正文只指标题后到下一个有效标题之前的文本，不包含子章节正文，避免重复导出。

## 6. 误识别合并与撤销

### 空章节删除

支持“删除空章节”（选中单章）及“清理空章节”（一次删除全部）。判断依据为标题后、下一个有效标题前的直属正文是否为空或仅含空白；卷、册等分组标题也适用，子章节正文不计入父标题的直属正文。删除后保留子章节并按剩余标题重建层级。

删除与合并分别记录：合并将原标题保留为正文，删除将空标题从预览与 EPUB 正文、NAV、NCX 中移除。Worker 保留不变的解码原文，根据删除行号创建工作副本；保留行分隔符以维持原文行号及章节 ID，预览与导出使用工作副本对应的区间。删除开头空标题产生的纯空白简介不单独导出。原文文件及原文字符、行数统计不变。

纠错历史同时保存合并行号和删除行号，支持混合操作撤销/重做及调整识别规则后重算。Worker 校验新删除目标，阻止直接删除有直属正文的章节；导入新文件时重置记录。若整本只有空标题，清理后沿用无标题文档的单正文占位，不恢复任何已删除标题。

### 误识别标题合并

“合并到上一章”在模型上表示取消当前标题边界，而不是删除原文或拼接多个正文副本。

执行规则：

1. 将所选标题的源行加入 ignoredHeadingLines。
2. 该标题行恢复为普通正文，与其后直到下一个有效标题之前的正文，一并接续到原文顺序中的前一个内容段。
3. 保留后续子标题，根据剩余有效标题重新构建目录。
4. 如果没有前一个有效标题，则并入“简介”内容段。
5. 记录可撤销命令，支持撤销和重做；原文不变。

例如：

```text
第一卷 开端
第一章 相逢
正文 A
第二卷 只是正文引用      ← 误识别，取消标题
正文 B
第二章 夜雨
正文 C
```

纠正后，“第二卷 只是正文引用”和正文 B 成为“第一章”的正文；“第二章”仍是章节，并归入“第一卷”。

同一解码文本内调整关键词或层级时，已取消标题的源行继续生效。更换文件或编码会使源行定位可能失效，需要明确提示重置纠错记录。撤销记录保存操作及必要配置快照，不保存整本正文快照。

## 7. 数据模型与关键约束

```ts
type HeadingRule = {
  id: string;
  keyword: string;
  level: number;
  kind: 'numbered' | 'unnumbered';
  enabled: boolean;
};

type Heading = {
  id: string; // documentId + 源行定位，规则重算时保持稳定
  lineIndex: number;
  start: number; // 统一换行文本中的 UTF-16 偏移
  end: number; // 标题行结束位置，不含行分隔符
  ruleId: string;
  level: number;
  title: string; // 原标题，不用匹配归一化结果覆盖
};

type ContentSection = {
  id: string;
  headingId?: string; // 简介或整本单章节可以没有源标题
  bodyStart: number;
  bodyEnd: number; // 半开区间，不包含下一个有效标题
};

type OutlineNode = {
  sectionId: string;
  parentId: string | null;
  children: string[];
};
```

正文按偏移引用，预览及导出时才取片段。源行以索引和偏移表示，避免为每一行创建多份字符串。

关键约束：源文本和源区间保持不变；每段正文按源顺序出现一次；有效标题作为标题呈现一次；取消的标题作为正文呈现一次；目录引用和阅读顺序一致。预览及导出按用户要求清理段首空白和章末空白行，其余文本保持一致。换行统一、标题展示和 XML 转义也是显式格式转换。

## 8. 预览与交互

建议电脑端采用左侧规则与目录、右侧正文预览的布局，顶部展示文件和编码，底部或顶部提供导出入口。

- 目录支持折叠、当前章节定位和误判合并操作；合并后提供即时撤销。
- 预览只加载当前内容段，超长内容段按行分批显示；目录超过阈值再使用虚拟列表。
- 每个非空行形成一个段落；清理行首空格（包括全角空格）、制表符及章末空白行，默认保留段间空行、行内空格和段尾空格。不猜测自然段，不自动拼接软换行。预览分页使用源文偏移，分页切在段落中间时不能误删该位置的空格。
- HTML/XML 特殊字符统一转义。TXT 中的 HTML 或脚本只作为文本展示，不通过原始 HTML 注入页面。
- “清理段间空行”设置保存在当前页面会话，默认关闭；预览区及导出窗口共享状态。开启后在预览渲染时滤掉空白段落，Worker 导出时跳过空白行，不生成空白段落 `<p>&#160;</p>`；不修改文本、章节区间、原文行号、目录或纠错历史。正文各段独立，不拼接非空行。空章节删除仍由独立操作控制。
- 与隐藏控制字符清理同时开启时，先清理控制字符及段首缩进，再判断空白行；即使遍历大量空行，导出仍按原文行数让出执行权，支持进度和取消。
- 预览用于核对标题、层级和文本，不承诺模拟阅读器字体、分页和所有 CSS 效果。
- 默认仅将小说留在当前会话内存；规则偏好可单独保存到本地，不默认持久保存正文。

## 9. EPUB3 导出与兼容策略

建议按 EPUB 3.3 规范设计首版，OPF 的 version 属性使用 `3.0`。生成 NAV 目录，并附带旧式 NCX；两份目录由同一目录树生成。EPUB3 规范允许为 EPUB2 阅读系统提供 NCX 等兼容内容，但这不等于所有旧阅读器均能读取。参考：[EPUB 3.3 及旧版兼容特性](https://www.w3.org/TR/epub-33/)。

建议文件结构：

```text
mimetype
META-INF/container.xml
OEBPS/content.opf
OEBPS/nav.xhtml
OEBPS/toc.ncx
OEBPS/text/section-000001.xhtml
OEBPS/text/section-000002.xhtml
...
```

生成要求：

- 书名、语言、唯一标识和修改时间写入元数据；作者为空时不虚构作者。
- 可选自动生成封面，默认关闭。使用必填书名，通过浏览器 Canvas 在本地生成 600 × 800 像素、白底黑字 PNG；不额外添加书名号，书名默认字号 72px、水平居中，文字块中心位于距顶 240 像素处。按实际字体测宽换行，必要时缩小字号，保证长书名完整。预览与导出共用绘制函数，导出等待字体就绪；生成失败明确报错，不静默跳过所选封面。
- 开启时添加 `images/cover.png` 与无 CSS 的 `cover.xhtml`，OPF 用 `cover-image` 标记 PNG，封面页位于 spine 最前，同时提供旧式 cover meta 与 guide 引用。章节 NAV/NCX、文件名和正文保持原有内容；关闭时不产生封面资源。封面格式和声明参照 [EPUB 3.3 manifest 资源属性](https://www.w3.org/TR/epub-33/#sec-item-resource-properties)。
- 每个有效标题至少对应一个内容文档，包括卷、册等分组标题；简介单独输出。
- 超长内容段可按段落拆成多个文件，建议从每片约 250KiB UTF-8 XHTML 开始实测；目录链接首片，spine 包含所有片段，保持连续阅读。
- 嵌套 NAV、NCX 使用相同层级和目标；所有目标 ID、manifest 和 spine 引用须可解析。
- 只输出语义 XHTML，不附带 CSS 文件、style 元素、行内 style 属性或样式表引用；OPF 不声明样式资源。字体、行距、缩进、段间距及长文本折行交由阅读器及用户设置处理。避免依赖脚本、远程资源、复杂布局及内嵌字体。
- 正文文本仍按原规则清理和转义，但不强制保留空白的视觉排版。保留空行时使用无 class 的 `<p>&#160;</p>`，开启清理段间空行时省略该段。网页界面及预览的 CSS 与 EPUB 输出独立。
- XML 不支持的字符在导出前按完整文档行号及当前工作文本的 UTF-16 字符偏移定位（从 0 开始）。默认阻止生成、不静默丢弃；导出窗口提供默认关闭的隐藏控制字符清理选项，仅移除正文及章节标题中 XML 禁止的 C0 控制字符（U+0000–0008、U+000B、U+000C、U+000E–001F），保留 TAB、LF、CR 及合法 Unicode。
- 清理只作用于输出序列化，源 TXT、Worker 文本、目录区间及预览不变；XHTML 标题/正文和 NAV/NCX 标题统一清理，按当前工作文本中的原始出现次数统计并在导出成功后显示。清理后的章末空行继续去除。书名、作者或其他损坏 Unicode 仍阻止导出，避免清理范围不明确。

容器打包必须保证 mimetype 是首个条目、内容恰为 `application/epub+zip`、不压缩、无 BOM 和额外字段；不能仅依赖 ZIP 库默认配置。参考：[OCF 容器要求](https://www.w3.org/publishing/epub32/epub-ocf.html#sec-zip-container-mime)。

采用浏览器 Blob 下载并及时释放 Object URL；分段生成 XHTML 和压缩输入，避免同时保留所有解压正文副本。输出 ZIP/Blob 仍可能占用完整文件内存，因此这不是恒定内存方案。

## 10. 验证与验收

| 类别       | 必须覆盖的情形                                                 | 验收要求                                             |
| ---------- | -------------------------------------------------------------- | ---------------------------------------------------- |
| 编码       | UTF-8/BOM、GBK/GB18030、UTF-16、Big5、判断失败                 | 可预览并手动纠正，不静默吞掉解码错误                 |
| 标题       | 中英文数字形式、全角数字、多级/缺级、无编号、自定义关键词      | 层级及原文顺序正确，无章节编号重排                   |
| 误判       | 句中关键词、独立行误判、首标题、多层节点、连续合并             | 标题转正文、子章节保留，撤销/重做可还原              |
| 文本完整性 | 简介、段首缩进清理、章末空行清理、段间空行、特殊字符、超长章节 | 按转换约定呈现一次，无正文遗漏或重复，源文及偏移不变 |
| EPUB 结构  | NAV/NCX 一致性、manifest/spine、链接、ZIP 头                   | 自动检查通过，引用可解析                             |
| 规范       | 代表性生成样本                                                 | EPUBCheck 无 error/fatal，warning 逐项解释或修复     |
| 阅读器     | 选定的现代阅读器及至少一个目标旧阅读器                         | 能打开、多级目录可用、正文顺序及字符正确             |
| 规模       | 1MiB、10MiB、20MiB，及高章节数样本                             | 导入、规则重算、预览、导出完成，进度和取消可用       |

解析、合并和 EPUB 结构使用核心单元测试；完整导入→纠错→下载使用少量端到端测试。性能记录参考电脑、浏览器版本、文件和章节数；在原型实测前不承诺具体转换秒数或内存峰值。

EPUBCheck 是开发及 CI 阶段的命令行验证工具，支持 EPUB2/3；无需将小说上传到在线验证服务，也不要求浏览器用户安装 Java。参考：[EPUBCheck 官方说明](https://www.w3.org/publishing/epubcheck/)。规范通过与真实阅读器兼容分别验收。

## 11. 实施顺序与建议目录

1. **文本与规则核心**：编码预览、行索引、规则模型、多级识别，先验证边界与源文本完整性。

4. **兼容与交付**：20MiB 样本实测、目标阅读器验证、取消和失败恢复、静态构建部署说明。

## 自定义正则高级规则

- 保留现有关键词规则，另设最多 20 条正则规则，每条包含稳定 ID、名称、表达式、层级和启用状态；数组顺序即优先级，正则先于关键词匹配，一行只采用第一条命中的规则。
- JavaScript 正则固定使用 `u` 标志，不开放 `g`、`y`、`m` 等标志；用户填写表达式正文，内部包装为完整行匹配。输入为逐行去除首尾空白后的文本，沿用 4–500 字的标题长度上限。
- 可用 `(?<title>...)` 提取显示标题；未定义该组时保留整行，已定义但未参与匹配或提取为空时明确报错。显示标题用于 UI、XHTML、NAV、NCX，源文本、原文行号和章节范围不变；合并时原标题行完整保留。
- 提供“测试文本”和“测试当前文件”，返回所有标题数量、正则命中数及前 20 条正则样例（原文行号、原标题、提取标题、规则名称、层级）。测试使用草稿规则，不提交目录或纠错状态；示例文本最多 20,000 字符。
- 文档 Worker 保留已提交原文与目录；含正则规则的加载、重算、纠错、测试任务交给一次性的独立匹配 Worker。主线程仅做结构校验，不编译或执行用户正则。匹配 Worker 启动限时 15 秒；就绪后若连续 2 秒无进度，文档 Worker 终止该任务并报错。按 4,000 行发送进度并让出执行权；这同时允许正在执行的单次灾难性回溯被外部终止。
- 取消会立即终止匹配 Worker，语法错误、空标题、超时或取消均不覆盖已有文档/目录。正则需先通过隔离校验再保存，沿用既有规则存储键，旧记录缺少正则字段时按空列表迁移。
- 匹配任务需复制源文本到独立 Worker；没有空章节删除时只返回目录，避免回传整本正文。该隔离会增加使用正则时的临时内存占用。无正则时继续在文档 Worker 内执行原流程。

## EPUB 转 TXT

- 新增独立转换窗口与 `useEpubConversion` 会话 Hook，复用 Worker 协议及客户端，每次转换创建独立 Worker；取消或关闭立即终止实例，不改变 TXT 工作台的原文、目录及纠错记录。成功后传输 UTF-8 字节缓冲，仅回传前 4,000 字符作预览。
- `core/epub/extract.ts` 读取 container、OPF manifest/spine，使用 fflate 选择性解压 XML/XHTML，以 xmldom 解析文本节点。xmldom 从开发依赖提升为运行依赖，锁定版本保持不变。只解析数据，不渲染书中 HTML、不执行脚本、不请求网络资源。
- 按 spine 顺序转换正文，包括 `linear="no"` 的补充文档；重复资源只提取一次。guide、landmarks 和结构语义指示的封面/目录被略过，锚点仅过滤所在区域，避免误删同文件中的实际章节。已有标题保留，不根据文件名或目录重新制造标题。
- 普通文本按 HTML 空白语义归并，块级内容和 br 转为换行，空段落保留，pre 保留换行及缩进，表格单元格用 TAB 分隔；正文文档之间空一行，输出 UTF-8 无 BOM、LF、末尾一个 LF。文本、图片和复杂排版并非无损互转。
- 缺失/无效结构、损坏或加密正文明确报错，不静默忽略缺章；仅字体混淆允许读取。图片型文档不执行 OCR；未标记的封面目录及仅通过外部 CSS 隐藏的文字不能完全自动判断。实际范围与用户说明见 [EPUB 转 TXT](EPUB_TO_TXT.md)。
- 顺序提取遵循 [EPUB spine](https://www.w3.org/TR/epub-33/#sec-spine-elem)，解析器使用 [xmldom](https://github.com/xmldom/xmldom)。
