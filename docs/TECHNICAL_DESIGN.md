# TXT 与 EPUB 互转技术设计

本文描述当前实现。[项目首页](../README.md) · [源码入口](STRUCTURE.md) · [验证与验收](VALIDATION.md)

## 架构与会话

拾页使用 React、TypeScript 和 Vite 构建静态单页应用。React Hook 保存页面状态，Web Worker 执行文本分析和转换。fflate 负责 EPUB ZIP 打包和解包，xmldom 解析导入的 EPUB XML／XHTML。应用无需业务后端；网页和 Worker 脚本由静态服务加载，小说内容不会作为网络请求发送。

```text
TXT File → 文档 Worker 解码 → 识别与纠错 → 当前目录
                                   ├─ 编号检查报告
                                   ├─ 按需取正文片段 → 网页预览
                                   └─ XHTML／OPF／NAV／NCX → EPUB ZIP → Blob 下载

EPUB File → 独立文档 Worker 实例 → 容器／OPF／spine → XHTML 文本
                                                   → TXT 字节 + 有限预览 → Blob 下载
```

TXT 工作台保留原始 File 以便重新解码，文档 Worker 保有解码原文、纠错工作文本和当前目录快照。界面接收目录、统计及按需预览；生成的文件字节通过可转移缓冲区返回。EPUB 转 TXT 复用文档 Worker 协议，每次转换使用独立实例，取消或关闭窗口时终止该实例。

`DocumentClient` 以请求 `id` 匹配进度和结果；`documentId` 标识已导入文档，`revision` 区分重算后的目录。预览按节 ID 和版本核对，编号报告额外核对检查设置。主要文档任务串行执行；取消会使当前任务失效，长任务在检查点报告进度并让出执行权。失败或取消的导入、重算不会覆盖已提交文档。

浏览器本地存储只保存已应用的关键词、正则和标题长度设置。正文、纠错历史、编号检查设置与确认、转换结果均为会话状态。下载使用 Blob 和 Object URL，延迟 60 秒释放 URL；生成任务完成并不等同于浏览器已写入下载文件。

## TXT 解码、识别与纠错

### 解码与范围

自动模式优先识别 UTF-16 LE／BE BOM，然后严格尝试 UTF-8（含 UTF-8 BOM）；失败后对可完整解码的 GB18030 和 Big5 候选评分，按常见中文字符、替换字符及控制字符判断，并标记为推测。手动模式可选择 UTF-8、GB18030、GBK、Big5、UTF-16 LE／BE。解码使用 `TextDecoder` 的严格模式；不接受零字节或纯空白输入。

解码后的原文统一 CRLF／CR 为 LF。扫描时逐行推进，不建立持久的逐行文本副本或完整行起始表。标题的 `lineIndex` 从 0 开始，界面行号从 1 开始；`headingStart`、`bodyStart`、`bodyEnd` 是工作文本中的 UTF-16 偏移，正文区间为半开区间。空章节删除保留分隔符和源行号，但可能改变工作文本偏移。源文件大小严格大于 50 MiB 时显示非阻断提示。

### 章节模型

| 模型                           | 主要职责                                                                                |
| ------------------------------ | --------------------------------------------------------------------------------------- |
| `HeadingRule`                  | 字面关键词、启用状态、编号／无编号类型、层级                                            |
| `RegexHeadingRule`             | 规则 ID、名称、单行表达式、启用状态、层级及列表优先级                                   |
| `Section`                      | 显示标题、源行号、标题和正文偏移、层级／深度／父 ID、空节和可疑提示、可选正则与编号信息 |
| `Outline` / `DocumentSnapshot` | 原文顺序的内容段与统计；快照额外带文件和编码信息、文档 ID 与版本                        |
| `Corrections`                  | 已并入正文和已删除空标题的源行号集合；撤销／重做保存这些记录                            |

识别在去除首尾空白的整行上进行。标题默认上限 60 个 Unicode 码点，可设为 4–500。每行先尝试启用的正则，采用首个整行命中；随后尝试转义后的字面关键词，较长关键词优先。默认层级为卷 → 册 → 章 → 回，无编号标题也按配置层级入树。段落邻接及部分标点产生“可能是正文引用”提示，不删除内容。

目录栈按原文顺序构建，缺少中间层级时直接挂到最近的上级，不生成虚构父章。卷、册等父节点的直属正文到下一个有效标题为止，避免在导出时重复包含子节正文。首标题前的内容用 `frontmatter` 表示，显示为“简介”；无标题时导出单节，节标题使用书名。

“并入上一节”忽略目标标题边界，保留该行及正文。“删除空章节”只允许新删除直属正文为空的标题，保留分隔符和子章节；若删除开头标题只留下空白简介，不单独导出该简介。每次重算从解码原文和纠错行号重建工作文本，撤销历史不保存整本正文快照。

### 正则隔离与编号检查

启用自定义正则时，文档 Worker 将匹配任务交给一次性 analysis Worker，避免卡住文档 Worker 的消息循环。启动超时为 15 秒；就绪后连续 2 秒没有进度即终止，主动取消也会终止隔离实例。标题扫描每 4,000 行提供检查点。包含启用正则的任务需复制源文本给隔离 Worker；没有删标题时只回传目录，复用原文。规则语法、限制和例子见[正则指南](REGEX_RULES.md)。

`title` 决定显示标题，`number` 决定用于检查的编号；无有效编号不会使有效标题匹配失败。识别阶段保存编号原值、解析值、类型和分篇，检查阶段不重读正文或重新执行用户表达式。

编号检查按类型、层级和可选的上级卷／册分组。缺号由排序后的不同编号计算，重复由同值聚合，顺序异常由原文相邻编号判断；缺号区间不逐个展开。时间复杂度 O(N log N)，额外空间 O(N)，N 为目录规模。默认检查全书的章和回，允许明确的上中下分篇；其他行为见[编号检查指南](NUMBERING_CHECK.md)。

## 预览与正文转换

- 目录按可见行窗口渲染；正文按需分页，默认每次读取约 18,000 个 UTF-16 代码单元，尽量在附近换行处结束。分页不会把段中空白当作段首缩进。
- 预览和导出统一去除段首制表符及 Unicode 空格分隔字符，去掉章末空白行，保留非空行中的其他空格与段尾空格。每个非空行独立成段；不重建自然段。
- “清理段间空行”在预览和导出共用状态，默认关闭。关闭时导出用 `<p>&#160;</p>` 表示空行；开启时跳过空白段。段间空行设置不改变章节范围。
- TXT 内容作为文本显示；XHTML 和包文档在序列化时转义特殊字符。网页样式与导出排版独立。

## EPUB3 导出

```text
mimetype
META-INF/container.xml
OEBPS/content.opf
OEBPS/nav.xhtml
OEBPS/toc.ncx
OEBPS/text/section-000001.xhtml
OEBPS/text/section-000002.xhtml
…
OEBPS/cover.xhtml        # 开启封面时
OEBPS/images/cover.png   # 开启封面时
```

- **容器与元数据**：`mimetype` 是首个 ZIP 条目，内容为 `application/epub+zip`，不压缩、无 BOM 或额外字段。OPF 使用 `version="3.0"`，保存书名、语言、UUID 和修改时间；作者留空时省略。参见 [W3C EPUB 3.3 容器与包文档](https://www.w3.org/TR/epub-33/)。
- **命名与拆片**：按 `documents.length + 1` 为每个内容文件分配 `section-NNNNNN` ID，数字至少六位。简介、分组和续片均独立占号。250 KiB 是正文段落标记的 UTF-8 软目标；阈值不含 XHTML 外壳和首片标题，单个超长段落完整保留。示例见[文件命名与拆片](TXT_TO_EPUB.md#xhtml-文件命名与拆片)。
- **目录与阅读顺序**：同一目录树生成 NAV、NCX；章节链接指向首片的 `#heading`，续片不重复输出 h1，所有内容文件按顺序写入 manifest 和 spine。附带 NCX 用于旧阅读器兼容，不另产 EPUB2。
- **封面**：Canvas 绘制 600 × 800 的 PNG，预览与生成共用函数。书名从 72 px 开始，按系统字体实际宽度与字素边界换行，必要时缩小；文字块中心距顶部约 240 px。封面资源标记 `cover-image`，封面页在 spine 最前，同时写入旧式 cover meta 和 guide；正文编号不受影响。
- **样式**：XHTML、OPF、NCX 和 XML 按层级换行缩进。EPUB 不打包 CSS，无样式表引用、style 元素或行内 style；实际显示由阅读器决定。
- **字符校验**：默认拒绝 XML 不合法字符，正文报错给出完整工作文档的 1 基行号和 0 基 UTF-16 偏移。可选清理只处理工作正文和章节标题的非法 C0（U+0000–0008、U+000B、U+000C、U+000E–001F），保留 TAB、LF、CR；统计按工作文本中出现次数计算，不因标题同时写入多份目录而重复计数。非法元数据和其他不合法 Unicode 仍报错。开启两种清理时，先处理控制字符与段首空白，再判断空行。

EPUB 分段生成并压缩，但输入和最终 ZIP／Blob 仍需内存，不是恒定内存的流式转换。

## EPUB 转 TXT

按 `container.xml` 定位 OPF，解析 manifest 和 spine，按 spine 顺序选择性解压并解析 XML／XHTML。相对路径及转义路径在 ZIP 内解析，拒绝需访问外部的正文资源。正文读取支持 UTF-8 和 UTF-16，不加载书内脚本、图片、字体、外部 DTD 或样式表。

转换根据 guide、landmarks、结构语义和显式隐藏标记略过相应区域，重复资源只提取一次。仅将已有标题和正文转成 UTF-8 无 BOM 文本，不根据 NAV／NCX 补造标题。附加的 `linear="no"` 内容仍按 spine 位置提取。每个文档间空一行，使用 LF 换行并保留末尾换行。

Worker 返回完整 TXT 字节及最多前 4,000 个 UTF-16 代码单元的预览（不截断代理对）。损坏结构、缺失的必要正文或正文加密会报错；非正文条目可略过，完全无可提取文本时提示 OCR。详见[提取行为与限制](EPUB_TO_TXT.md)。

## 验证边界

自动测试检查转换内容、引用、取消、失败恢复及大文件；浏览器操作、EPUBCheck 规范检查和阅读器实机验收各自记录。对于兼容问题，应记录阅读器型号、版本和复现样本。命令及已有证据见[验证与验收](VALIDATION.md)。
