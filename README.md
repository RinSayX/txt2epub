# 拾页 · TXT 与 EPUB 本地互转

纯浏览器本地处理的小说整理与转换工具。导入 TXT、整理章节、预览正文，导出带有多层目录的 EPUB3 电子书；也可将未加密的 EPUB 转换为 UTF-8 TXT。小说不上传到服务端。

## 本地运行

推荐 Node.js 24，使用 npm 安装依赖：

```sh
npm ci
npm run dev
```

项目通过 `.npmrc` 使用当前目录下的 `.npm-cache/` 缓存，避免用户全局 npm 缓存的权限问题。该缓存已加入 `.gitignore`，安装时无需修改全局目录权限。

打开终端显示的本机地址（默认 `http://127.0.0.1:5173`）。首次运行需联网安装依赖。依赖安装完毕后，转换过程无需联网；静态网页首次加载仍需要本地或远程服务器。

```sh
npm run build     # 类型检查并生成 dist/
npm run preview   # 预览构建产物
npm test          # 编码、识别、纠错、EPUB 结构与内容测试
npm run test:scale # 1/10/20/51 MiB、Worker 导入逻辑及 16000 章节验收
npm run format    # 格式化源码、样式及文档
npm run format:check # 检查格式，不修改文件
```

`dist/` 可部署到静态托管服务，无需后端。请通过 HTTP(S) 访问，直接双击 HTML 文件不支持 Worker 和模块加载。

## 已实现功能

- 提供独立的“EPUB 转 TXT”窗口，支持选择或拖入 EPUB2/EPUB3，按 OPF spine 阅读顺序提取已有标题、段落和换行，检查前 4,000 字符预览后下载 UTF-8 TXT。封面、目录区域、图片、脚本与样式略过，不覆盖当前 TXT 工作台。支持转换进度与取消，超过 50 MiB 时提示但不阻止。具体提取规则与限制见 [EPUB 转 TXT 使用说明](docs/EPUB_TO_TXT.md)。
- 支持导入大文件 TXT，不设置文件大小硬上限。仅超过 50 MiB 时提示可能需要更多时间和内存，仍自动继续导入；恰好 50 MiB 不提示。实际处理能力取决于浏览器和设备资源。
- 支持 UTF-8、GBK、GB18030、Big5、UTF-16LE/BE，提供自动判断与手动切换。
- 自动识别中文数字、阿拉伯数字、全角数字章节编号。
- 多层章节目录，默认“卷 → 册 → 章 → 回”；支持关键词增删、启停、层级排序和同级关键词。
- 高级规则支持自定义 JavaScript 正则：逐行完整匹配，按规则优先顺序先于关键词规则；可用 `(?<title>...)` 提取显示标题，并设置名称、启用状态和层级。提供前置序号示例、测试文本和测试当前文件，显示总命中数及前 20 条原文行号/原标题/提取标题；测试不修改目录。
- 正则在独立 Worker 中编译与执行，启动限时 15 秒，就绪后连续 2 秒无进度会终止任务；超时、语法错误或取消不覆盖已有文档与目录。最多 20 条正则，每条表达式最多 1,000 字符，测试文本最多 20,000 字符；仍受标题长度上限约束。
- 支持“序章、楔子、尾声、后记、番外”等无编号标题及带明确分隔符的副标题。
- 可搜索、折叠的目录；正文按需预览、分页加载，可调整预览字号。
- 将误判标题并入上一节：原标题行保留为正文，子章节保留并重建层级；支持撤销/重做和快捷键 `⌘/Ctrl Z`、`⌘/Ctrl Shift Z`。
- 删除只有标题、直属正文为空或仅有空白的章节：支持删除选中章节及一键清理全部，保留子章节并重建层级；删除的标题不会并入正文或出现在 EPUB 中，支持撤销/重做。空的卷、册等分组标题也会被清理。源 TXT 不变。
- 调整识别规则后保留当前文件的纠错记录；更换文件或编码前提示重置纠错。
- 预览与导出统一去除每段开头的空格、全角空格和制表符，以及章节末尾的所有空白行；默认保留段落之间的空行、行内和段尾空格及特殊字符，不自动拼接自然段。源 TXT 不变。
- 预览区与导出窗口提供同步的“清理段间空行”开关（默认关闭）。开启后自动略过空行及仅含空格、全角空格、制表符的行，不再生成空白段落标签；每个正文段落仍独立，章节标题和源文区间不变。取消勾选可立即恢复预览中的空行，设置仅在当前页面会话有效。
- 编辑书名、可选作者及语言；导出 EPUB3，包含 NAV 与 NCX 多级目录、OPF 阅读顺序和 UTF-8 XHTML。选择“简体中文”时，元数据及 XHTML 的语言代码统一使用 `zh-CN`。
- 导出窗口提供“自动生成封面”（默认关闭）：书名必填，在浏览器本地生成 600 × 800 像素 PNG，白底黑字，仅显示书名，默认字号 72px，水平居中、位置偏上，不额外添加书名号。长书名自动换行，必要时缩小字号；可实时预览。封面嵌入 EPUB，声明为封面图片并放在阅读顺序最前，不改变章节目录、正文或章节文件名。不勾选时不生成封面；不上传文件、不依赖网络字体，具体字形随设备系统字体略有差异。
- 导出窗口可勾选“清理不兼容的隐藏控制字符”（默认不勾选），移除正文及章节标题中 XML 禁止的 C0 控制字符，如 U+001A；完成后显示清理数量，源 TXT 和预览不变。正常文字、换行、制表符、emoji 等保留。未勾选时定位报错，不静默删除；损坏的 Unicode 字符和书名、作者中的非法字符仍需手动修正。
- EPUB 内的 XHTML、OPF、NCX 和 XML 使用换行及两空格缩进，方便在电子书编辑器中修改；每个正文段落独立一行，代码缩进位于标签之外，不会成为正文缩进。
- 导出 EPUB 不附带 CSS 文件、内嵌样式或行内样式，字体、字号、行距、缩进和段间距由阅读器及用户设置决定。标题、段落和目录保留语义结构；正文文件中的行内空格仍保留，但显示时可能由阅读器折叠。网页预览只用于文本和目录校对。
- 长章节按段落拆分为内容文件，解析与导出在 Web Worker 中运行，提供进度和取消。
- 自带合成示例小说，可直接体验并纠正一处有意保留的误识别。

## 使用方法

1. 选择 TXT 或拖入中央导入区，也可点击“试用示例小说”。
2. 检查正文编码；若乱码，在文件信息栏手动切换。自动推测的传统编码需人工核对。
3. 在“识别规则”添加关键词、选择层级，点击“应用识别规则”。层级数字越小，级别越高。
4. 在目录选中误识别的标题，点击“并入上一节”。如果没有上一节，内容归入“简介”。
5. 对只有标题的章节，选中后点击“删除空章节”，或点击“清理空章节”一次删除全部。空的分组标题也会删除，有正文的子章节保留。
6. 如果希望去除段落之间的空行，勾选预览区的“清理段间空行”；也可在导出窗口设置，两处开关同步。
7. 点击“导出 EPUB”，填写书名等信息。如需封面，勾选“自动生成封面”并检查预览，再生成并下载电子书。书名会从 TXT 文件名预填，可自行修改；空书名或仅含空白时不能导出。

小说和纠错记录仅保留在当前页面会话中，刷新或关闭页面后需重新导入。浏览器本地存储仅保存识别规则，不保存小说正文。

特殊章节格式的配置步骤、可复制表达式、标题提取、匹配优先级、测试方法和常见问题，见 [自定义正则使用指南](docs/REGEX_RULES.md)。

从 EPUB 提取文本：点击页面上方“EPUB 转 TXT”，选择或拖入电子书，待提取完成后检查预览，点击“下载 TXT”。文件名优先使用 EPUB 元数据中的书名，缺失时沿用原 EPUB 文件名。不支持 DRM 加密正文及图片文字识别（OCR）；关闭转换窗口后需重新选择 EPUB。

## 验证与兼容范围

核心测试覆盖编码、多层与缺层目录、误判合并及还原、原文区间完整性、特殊字符转义、NAV/NCX/manifest/spine 引用及长章节拆分。

浏览器操作已验证示例导入、误判合并、撤销、重做、自定义规则重算和实际下载。浏览器生成的示例文件通过 EPUBCheck 5.4.0：0 fatal、0 error、0 warning。

另已通过 1/10/20/51 MiB 和 16,000 章节规模测试，Worker 导入逻辑使用真实 51 MiB 文件完成读取和预览验证。浏览器已验证恰好 20 MiB 文件的导入、取消导出和重新导出；已验证的导出样本通过 EPUBCheck。详情见 [验收记录](docs/VALIDATION.md)。

如已安装 EPUBCheck，可在本机检查导出文件：

```sh
java -jar /path/to/epubcheck.jar /path/to/book.epub
```

只输出 EPUB3。附带 NCX 以增强旧阅读器兼容性，不承诺符合 EPUB2 或兼容全部旧设备；目标阅读器尚待指定及实机验证。页面预览用于文本和目录校对，不模拟阅读器分页。

单个超长段落不会被强行改写，250 KiB 的 XHTML 拆分阈值为按段落拆分的软目标。发现 XML 不支持的字符时，导出默认定位提示并阻止生成；正文中的非法 C0 控制字符可在导出窗口显式选择清理。错误行号按完整文档计算，字符偏移按当前工作文本的 UTF-16 索引计算（从 0 开始）；空章节删除保留源行号，但会改变工作文本的字符偏移。

## 技术结构

React + TypeScript + Vite，fflate 负责 EPUB 打包与解包，xmldom 在 Worker 中解析 EPUB 的 XML/XHTML；核心解析和导出与 UI 分离。

```text
src/
  app/             页面组合、文档会话流程、本地规则偏好
  components/      导入、目录、规则、预览、文件信息及弹窗
  core/            编码识别、目录构建、段落清理、数据模型和默认规则
    epub/          EPUB 打包、文本提取、文档模板、XML 校验与转义
  workers/         Worker 入口、消息协议、主线程客户端
  lib/             浏览器下载、Canvas 封面绘制和显示格式工具
  examples/        应用内的示例小说
  styles/          全局、工作台、阅读区、面板和响应式样式
  config.ts        文件提示阈值、编码选项等应用配置
  main.tsx         应用入口
tests/
  core/            编码、章节及 EPUB 测试
  components/      界面提示测试
  workers/         Worker 导入测试
  scale/           大文件及高章节数验收
docs/              技术方案、验收记录和结构说明
```

特殊标题可在“识别规则 → 高级规则 · 自定义正则”点击“添加前置序号示例”。该示例识别 `233.第233章 比试`、`２３３．第２３３章 比试` 等格式，分别提取 `第233章 比试`、`第２３３章 比试` 作为显示标题，不转换编号的字符形式。表达式只填正文，不加 `/ /` 或标志；固定使用 Unicode 模式。未定义 `title` 捕获组时保留完整标题行；存在该组但结果为空时会报错。调整后先测试，再点击“应用识别规则”。已应用的正则规则与关键词规则一同保存在当前浏览器，原有规则设置自动兼容。详细示例见 [自定义正则使用指南](docs/REGEX_RULES.md)。

详细需求决定、架构和验收标准见 [技术方案](docs/TECHNICAL_DESIGN.md)，目录职责及本次整理说明见 [项目结构](docs/STRUCTURE.md)。

`node_modules/`、`.npm-cache/`、`dist/`、`artifacts/` 属于本地依赖、缓存或生成产物，均不纳入 Git。`artifacts/` 仅在测试或验证时生成。源码和页面样式使用 Prettier 统一格式；构建前直接检查类型，不再在根目录产生 TypeScript 构建状态文件。
